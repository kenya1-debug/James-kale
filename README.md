# James Kale & Co. Advocates: website

Next.js 16 (App Router) · TypeScript · Tailwind v4 · Supabase · Vercel

## 1. Create the project locally
```bash
npm install
cp .env.example .env.local     # Windows: copy .env.example .env.local
```

## 2. Supabase
1. Create a project (choose the region closest to Kenya, e.g. Frankfurt or London).
2. SQL Editor → run `supabase/migrations/0001_schema.sql`, then `supabase/seed.sql`.
3. Project Settings → API: copy the Project URL and the **publishable** key into `.env.local`.
   (If your project still shows the legacy `anon` key, paste it into the same variable; it works the same way.)
4. Authentication → Providers → Email: **disable "Allow new users to sign up"**.
5. Authentication → Users → Add user (email + password, tick auto-confirm).
6. Promote that user (SQL Editor):
   ```sql
   update public.profiles set role = 'admin', is_active = true where id = '<USER_UUID>';
   ```
7. Authentication → URL Configuration: Site URL `http://localhost:3000`; add your Vercel and production URLs later.

## 3. Run
```bash
npm run dev
```
Open http://localhost:3000, then http://localhost:3000/sw, then http://localhost:3000/admin.

## 4. Optional: typed database
```bash
npx supabase login
SUPABASE_PROJECT_ID=your-ref npm run types
```
Then pass the `Database` type to the clients in `src/lib/supabase/*`.

## Verification checklist
- `/` shows the English hero, `/sw` shows Kiswahili, `/en` redirects to `/`.
- `/admin` redirects to `/admin/login` when signed out.
- Wrong password shows "Invalid email or password."
- Correct admin login lands on `/admin`; Sign out returns to login.
- A user with `is_active = false` cannot get in.
- `npm run typecheck` and `npm run build` pass.

## Phase 3 notes
- Public content is read with a cookie-less client (`src/lib/supabase/public.ts`) so pages are statically generated and revalidated hourly.
- Contact numbers live in `site_settings` → `firm` (phone, whatsapp, email). Until set, call/WhatsApp buttons are hidden.
- Testimonials stay hidden until `features.show_testimonials` is true AND at least one testimonial is published.
- Legal pages (`src/content/legal.ts`) are drafts: James must review them before launch.

## Phase 4 notes
- Run `supabase/migrations/0002_rate_limit.sql` in the SQL Editor (adds the rate-limit table and function).
- Fill `RESEND_API_KEY`, `NOTIFY_EMAIL_TO`, `NOTIFY_EMAIL_FROM`, `RATE_LIMIT_SALT` in `.env.local`. Restart `npm run dev` after editing it.
- Until a domain is verified in Resend, send from `onboarding@resend.dev` and set `NOTIFY_EMAIL_TO` to the email on your Resend account.
- Optional Turnstile: set `NEXT_PUBLIC_TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY` (leave blank to rely on honeypot + rate limiting).
- Notification emails omit the client's message text by default (confidentiality). Set `EMAIL_INCLUDE_DETAILS=true` to include it.

## Phase 5 notes (admin dashboard)
- No new SQL. Run `npm install` (adds Tiptap and sanitize-html).
- Roles: **staff** see Dashboard, Consultations and Messages. **admin** also gets Blog posts, Practice areas, FAQs, Testimonials, Availability, Site settings and Team.
- Article HTML is sanitised on every save (allow-list), and only images from our own storage bucket are kept.
- Uploaded images are resized to 1600px and converted to WebP in the browser before upload.
- Saving content refreshes the public site immediately (`revalidatePath`).

## Phase 6 notes (SEO, security, analytics)
- `sitemap.xml`, `robots.txt`, social preview image and favicon are generated by the app.
- Every page has canonical + hreflang (en/sw) + Open Graph + Twitter tags (`src/lib/seo.ts`), and JSON-LD for the firm, FAQs, breadcrumbs, articles and the advocate.
- Analytics (Plausible and/or Google Analytics) load only after a visitor accepts the cookie banner. Set `NEXT_PUBLIC_PLAUSIBLE_DOMAIN` or `NEXT_PUBLIC_GA_ID`. With neither set, no banner is shown.
- The Content-Security-Policy applies to production builds only. Trial it with `CSP_REPORT_ONLY=1`.
- See `docs/google-business-profile.md` and `docs/qa-checklist.md`.
